# Velog Posting Guide

## 작성 대상
- 가비서를 통해 실제로 진행한 기술 작업/자동화/인프라 정리
- 회고보다 기술 구현 내용, 구조 변경, 설정 포인트를 우선한다.

## 기본 톤
- 작업일지보다 기술 블로그에 가깝게 작성
- 감상보다 문제/설계/구현/결과 중심
- 필요 시 코드, JSON, YAML, 프롬프트 일부를 포함
- 설명은 `배경 → 문제 → 변경 내용 → 결과` 흐름을 우선한다.

## 스킵 기준
- 실질 작업이 거의 없는 날
- 공개용으로 정리할 가치가 부족한 날
- 기술적 설명거리보다 단순 잡담 비중이 큰 날

## 공개 전 점검
- 비밀값 제거
- 내부 경로/도메인/개인정보 과다 노출 여부 확인
- 외부 계정명, 내부 식별자, 개인 워치리스트 대상이 직접 노출되지 않도록 일반화 처리
- 코드/설정 예시가 있으면 공개 가능한 수준인지 확인
- 문장 다듬기
- 제목 개선
- 제목 아래 고지 문구 포함 여부 확인

## 해시태그
제목 바로 아래에 글 주제에 맞는 해시태그 한 줄을 넣는다.

규칙:
- 첫 번째 해시태그는 반드시 `#OpenClaw`
- 그 뒤에 주제 태그를 붙인다.

예시:
`#OpenClaw #가비서 #자동화`
`#OpenClaw #n8n #Daily브리핑`
`#OpenClaw #RSSHub #인프라 #자동화`

## 고지 문구
해시태그 아래에는 아래 문구를 넣는다.

> _이 글은 하루 동안 진행한 작업을 AI로 정리한 초안을 바탕으로, 사람이 검수·수정해 게시하는 기록입니다._

## 권장 구조
- 배경
- 문제
- 변경 내용
- 핵심 설정 / 코드
- 결과
- 정리

## 권장 제목 패턴
- `<문제/구조>를 <어떻게 바꿨는지>`
- `<자동화/워크플로우/인프라>를 <어떻게 정리했는지>`
- `<구현 주제>와 <적용 결과>`
