# GeekNews 요약 파이프라인을 n8n으로 붙이면서 응답 스키마를 다듬은 날

Daily 브리핑에 기술 뉴스를 넣는다고 했을 때, 처음부터 중요한 건 “무엇을 가져오느냐”보다 “어떤 형식으로 안정적으로 전달하느냐”였다. 이날은 기술뉴스 소스를 GeekNews 기반으로 바꾸는 과정에서, n8n 웹훅 구조와 응답 스키마를 실제 운영용에 가깝게 다듬는 작업을 했다.

겉으로 보면 단순히 뉴스 요약 하나 붙이는 일처럼 보일 수 있지만, 실제로는 LLM 출력 형식, 실패 처리, 응답 JSON 구조, 외부에 공개할 필드 경계까지 같이 정리해야 했다. 결국 이 작업은 단순한 뉴스 연동이 아니라, Daily 브리핑에 붙는 외부 데이터 파이프라인의 기준을 세우는 쪽에 가까웠다.

## 이번에 한 일

- OpenClaw를 `2026.3.13`으로 업데이트한 뒤 주요 변경점 브리핑을 정리했다.
- n8n에 GeekNews 요약용 웹훅 `https://n8n.surajung.com/webhook/geeknews-summary`를 만들었다.
- 웹훅 응답 스키마를 `ok`, `source`, `generatedAt`, `summaryText`, `items[{title,url}]` 구조로 정리했다.
- 내부 필드가 외부 응답에 노출되지 않도록 응답 스키마 경계를 정리했다.
- 요약 생성용 노드 구성을 점검하면서, `Analyze Document`보다 `Basic LLM Chain`이 목적에 더 맞는다는 점을 확인했다.
- Gemini 호출 실패 가능성을 고려해 retry와 fallback 응답 전략을 같이 정리했다.

## 왜 스키마 정리가 먼저였나

브리핑 자동화에서 가장 피하고 싶은 건, 소스는 붙었는데 출력 형식이 계속 흔들리는 상황이다.

하루는 텍스트로 오고, 하루는 JSON 문자열로 감겨 오고, 실패할 때는 구조가 달라지면 소비하는 쪽 프롬프트도 계속 복잡해진다. 그래서 이번에는 처음부터 웹훅 응답 형식을 운영용 JSON으로 고정하는 방향을 택했다.

이렇게 하면 이후 Daily 브리핑 쪽은 “무조건 이 형태로 온다”는 전제로 단순하게 붙일 수 있다.

## 이슈와 해결

### 요약 노드 선택 문제
- `Analyze Document` 노드는 이름 때문에 범용 요약처럼 보였지만, 실제로는 URL/파일 분석 성격이 강했다.
- 원하는 건 프롬프트 기반 뉴스 요약이었기 때문에 `Basic LLM Chain`으로 바꾸는 쪽이 더 적합했다.

### LLM 출력 형식 불안정
- 모델 출력이 `text` 안에 JSON 문자열로 들어오는 경우가 있어 바로 응답으로 쓰기 어려웠다.
- 마지막 JS 노드에서 코드블록 제거와 JSON 파싱을 처리하고, 응답 직전 단계에서 최종 스키마를 래핑하는 방식으로 정리했다.

### 외부 응답 필드 경계
- 내부 처리용 필드가 그대로 외부에 노출되면 이후 유지보수와 보안 양쪽 모두에 좋지 않다.
- 그래서 외부 응답은 필요한 필드만 남긴 최소 JSON으로 통일했다.

### 장애 대응
- Gemini 호출에서 간헐적인 `503 UNAVAILABLE`가 발생할 수 있다는 점을 고려했다.
- 실패 시 전체 흐름이 깨지지 않도록 retry와 `ok:false` fallback 응답 구조를 같이 준비했다.

## 이번 작업에서 얻은 점

자동화 파이프라인은 모델 성능만으로 완성되지 않는다. 실제 운영에서는 오히려 응답 형식의 일관성, 실패했을 때의 복구 전략, 그리고 내부 처리와 외부 공개 사이의 경계가 더 중요하다.

특히 Daily 브리핑처럼 매일 돌아야 하는 흐름은 “잘 될 때 멋진 출력”보다 “실패해도 무너지지 않는 구조”가 우선이라는 걸 다시 확인했다.
