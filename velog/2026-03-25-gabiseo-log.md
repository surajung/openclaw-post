# AI가 생성한 Velog 초안을 자동 검증하도록 하네스와 validator를 붙인 방법

#OpenClaw #Velog #자동화 #Markdown #검증

## 한줄 요약
Velog 초안 자동화에 구조 검증용 validator와 작성 기준 하네스를 추가해, 생성만 되는 문서가 아니라 커밋 가능한 게시 후보만 통과시키는 흐름으로 바꿨다.

## 배경

전날 작업을 정리해 Velog용 Markdown 초안을 만드는 자동화는 이미 동작하고 있었습니다. 다만 실제 운영 관점에서는 "초안이 만들어진다"와 "게시 후보로 관리할 수 있다" 사이에 차이가 있었습니다.

문서 자동화는 출력 품질이 조금만 흔들려도 후속 작업이 번거로워집니다. 특히 기술 블로그 초안은 아래 조건이 같이 맞아야 합니다.

- 제목, 해시태그, 요약, 본문 섹션 구조가 일정할 것
- 공개용 고지 문구 위치가 고정될 것
- placeholder 같은 미완성 문자열이 남지 않을 것
- 코드 블록이 깨지지 않을 것
- 검증을 통과한 결과만 저장소에 반영될 것

이번 작업의 목적은 생성 모델의 문장 품질을 더 높이는 것이 아니라, **초안 자동화 앞단에 문서 하네스와 validator를 붙여 결과물을 운영 가능한 형태로 고정하는 것**이었습니다.

## 문제

기존 흐름은 초안 생성 자체에는 문제가 없었지만, 운영 측면에서는 몇 가지 빈틈이 있었습니다.

첫째, 작성 규칙이 프롬프트와 문서에 분산돼 있으면 산출물 형식이 조금씩 흔들릴 수 있습니다. 예를 들어 `## 한줄 요약` 같은 필수 섹션이 빠지거나, 고지 문구 위치가 바뀌는 식의 문제가 생길 수 있습니다.

둘째, Markdown 문서는 작은 형식 오류가 실제 게시 직전에서야 드러나는 경우가 많습니다. placeholder 미치환, 코드 펜스 불균형, 필수 섹션 누락은 생성 단계에서는 넘어가도 게시 직전 품질을 떨어뜨립니다.

셋째, 자동 생성 후 바로 git commit/push를 수행하면, 형식이 깨진 초안까지 저장소에 쌓일 수 있습니다. 결국 품질 보증 없이 배포되는 셈이라 자동화의 이점이 줄어듭니다.

정리하면 문제는 글쓰기 품질보다 **출력 규칙의 강제력과 저장 전 검증 부재**였습니다.

## 변경 내용

이번에는 Velog 초안 자동화에 하네스 문서와 validator를 함께 추가했습니다.

- `posts/velog/AGENTS.md`: 초안 작성 규칙의 기준 문서
- `posts/scripts/validate-velog-draft.cjs`: 구조 검증 스크립트
- cron 지시문/운영 규칙: validator 통과 후에만 git add/commit/push 수행

핵심 변경은 아래 네 가지입니다.

### 1) 작성 규칙의 기준 문서를 단일화

초안 작성 시 어떤 구조를 따라야 하는지 `posts/velog/AGENTS.md`에 모았습니다. 이 문서는 제목, 해시태그, 필수 섹션, 고지 문구 위치, 코드 블록 규칙까지 한 곳에서 정의합니다.

이렇게 하면 프롬프트가 길어지더라도 실제 기준은 문서 파일 하나로 수렴합니다. 이후 규칙 변경도 "프롬프트 수정"이 아니라 "하네스 수정"으로 다룰 수 있습니다.

### 2) Markdown 결과물을 코드로 검증

문서 구조를 사람이 눈으로만 확인하지 않고, Node 스크립트로 검사하도록 만들었습니다. 초안이 생성된 뒤 아래 항목을 자동으로 확인합니다.

- `# `로 시작하는 제목 존재 여부
- `#OpenClaw`로 시작하는 해시태그 라인 존재 여부
- `## 한줄 요약` 섹션이 정확히 1개인지
- `## 배경`, `## 문제`, `## 변경 내용`, `## 핵심 설정 / 코드`, `## 결과`, `## 정리` 존재 여부
- 문서 최하단의 고지 문구 존재 여부
- placeholder 미치환 문자열 존재 여부
- fenced code block 균형 여부

### 3) 코드 블록 검사 시 본문과 예시를 분리

validator는 코드 블록 내부 내용 때문에 오탐이 생기지 않도록, 먼저 fenced block을 치환한 뒤 섹션/placeholder를 검사합니다. 문서 본문 규칙과 예시 코드 영역을 분리해서 보는 방식입니다.

이 접근 덕분에 예시 코드 안의 특수 문자열 때문에 본문 검증이 흔들리는 문제를 줄일 수 있습니다.

### 4) 검증 성공 이후에만 git 반영

자동화 마지막 단계도 바꿨습니다. 이제는 초안 생성 직후 바로 push하지 않고, validator를 통과한 경우에만 아래 순서로 반영합니다.

1. draft 생성
2. validator 실행
3. 통과 시 `git add -A`
4. `git commit`
5. `git push`

즉, 생성과 저장을 분리해 "쓸 수 있는 문서만 저장소로 보낸다"는 게 이번 변경의 핵심입니다.

## 핵심 설정 / 코드

이번 작업에서 중요한 부분은 validator가 문서 구조를 어떻게 고정하느냐였습니다. 실제 스크립트 핵심은 아래와 비슷합니다.

```js
const disclaimer = '> _이 글은 하루 동안 진행한 작업을 AI로 정리한 초안을 바탕으로, 사람이 검수·수정해 게시하는 기록입니다._';
const strippedText = text.replace(/(^|\n)(`{3,})[\s\S]*?\n\2/g, '\n[CODE_BLOCK]\n');

const placeholderMatches = strippedText.match(/\{\{[^}]+\}\}/g) || [];
const summaryMatches = strippedText.match(/^## 한줄 요약$/gm) || [];

const requiredSections = [
  '## 배경',
  '## 문제',
  '## 변경 내용',
  '## 핵심 설정 / 코드',
  '## 결과',
  '## 정리',
];
```

검증 실패 시 바로 종료하도록 처리해 후속 git 단계를 막습니다.

```js
if (errors.length > 0) {
  console.error(`VELOG_DRAFT_INVALID: ${path.basename(filePath)}`);
  process.exit(1);
}

console.log(`VELOG_DRAFT_VALID: ${path.basename(filePath)}`);
```

운영 명령도 단순하게 유지했습니다.

```bash
cd /Users/surajung/.openclaw/workspace/posts
node scripts/validate-velog-draft.cjs velog/YYYY-MM-DD-gabiseo-log.md
```

이 구조의 장점은 프롬프트가 다소 흔들려도 마지막에 결과물을 문서 규칙으로 한 번 더 걸러낼 수 있다는 점입니다.

## 결과

변경 이후 Velog 초안 자동화는 단순 생성 파이프라인에서 **생성 + 구조 검증 + 저장소 반영 제어** 흐름으로 바뀌었습니다.

얻은 효과는 명확합니다.

- 초안 형식이 흔들려도 자동으로 잡아낼 수 있다.
- 미완성 placeholder나 섹션 누락 같은 실수를 저장 전에 차단할 수 있다.
- 공개용 고지 문구 위치 같은 운영 규칙을 코드로 강제할 수 있다.
- 저장소에는 검증된 초안만 남기게 된다.

특히 의미 있었던 점은, AI 출력 품질 문제를 모델 튜닝으로만 보지 않고 **문서 스키마 검증 문제로 분해했다**는 부분입니다. 운영 자동화는 생성 정확도만큼 실패 조건을 어디서 막느냐가 중요합니다.

## 정리

AI로 기술 블로그 초안을 만드는 자동화는 생각보다 쉽게 만들 수 있습니다. 하지만 실제로 오래 굴리려면 "잘 써주는가"보다 "형식이 깨졌을 때 어디서 막는가"가 더 중요합니다.

이번 작업은 Velog 초안 자동화에 별도 validator와 하네스를 붙여, 프롬프트 기반 생성 흐름에 문서 품질 게이트를 추가한 작업이었습니다.

비슷한 자동화를 운영한다면 아래 순서로 접근하는 편이 안정적입니다.

- 작성 규칙을 단일 문서로 고정한다.
- 결과물 검사를 스크립트로 자동화한다.
- 검증 통과 뒤에만 저장소 반영을 허용한다.

이 방식이면 AI가 글을 "대충 그럴듯하게" 쓰는 수준을 넘어, 실제 운영 가능한 초안 생산 파이프라인으로 발전시킬 수 있습니다.
