# AI가 만든 Velog 초안을 바로 게시하지 않기 위해 템플릿과 가이드를 손본 방법

#OpenClaw #Velog #자동화 #프롬프트엔지니어링

> _이 글은 하루 동안 진행한 작업을 AI로 정리한 초안을 바탕으로, 사람이 검수·수정해 게시하는 기록입니다._

## 배경

전날 작업을 바탕으로 Velog용 Markdown 초안을 자동 생성하는 흐름은 이미 만들어둔 상태였습니다. 다만 초안이 실제 게시 직전 문서로 쓰이려면, 단순히 글이 생성되는 것만으로는 부족했습니다.

공개 초안에는 몇 가지 추가 조건이 필요했습니다.

- 글 목록 미리보기에서 불필요한 문구가 앞에 노출되지 않을 것
- 글 전체를 한 문장으로 빠르게 파악할 수 있을 것
- 템플릿, 가이드, 실제 생성 결과가 같은 규칙을 따를 것
- 사람이 후속 검수할 때 어디를 보면 되는지 구조가 명확할 것

이번 작업은 기능 추가보다도, AI 초안을 공개 가능한 문서 형식으로 다듬는 운영 규칙 정리에 가까웠습니다.

## 문제

초기 초안은 내용 자체는 나쁘지 않았지만, 게시용 문서로는 몇 가지 불편이 있었습니다.

첫째, 템플릿과 실제 생성 글의 구조가 완전히 고정돼 있지 않았습니다. 그 결과 초안마다 정보의 배치가 조금씩 흔들릴 수 있었습니다.

둘째, 공개용 고지 문구 위치가 글 상단에 있으면 목록 미리보기에서 반복적으로 보일 가능성이 있었습니다. 이 문구는 필요하지만, 본문보다 먼저 보이는 것은 글 가독성 측면에서 손해였습니다.

셋째, 글 전체를 요약하는 짧은 문장이 별도 섹션으로 분리돼 있지 않아, 사람이 검수할 때 핵심을 빠르게 확인하기 어려웠습니다.

결국 문제는 생성 품질 자체보다도 **출력 포맷의 일관성과 게시 전 검수 효율**이었습니다.

## 변경 내용

이번에는 Velog 초안 자동화에서 사용하는 산출물 3가지를 함께 정리했습니다.

- 실제 초안 파일
- 초안 템플릿(`TEMPLATE.md`)
- 작성/검수 기준 문서(`POSTING-GUIDE.md`)

핵심 변경은 아래와 같습니다.

### 1) `## 한줄 요약` 섹션 추가

본문 초반에 한 문장 요약을 고정 섹션으로 넣도록 템플릿을 수정했습니다. 이 변경으로 초안 검수 시 아래를 빠르게 판단할 수 있게 됐습니다.

- 이 글이 기술적으로 무엇을 말하려는지
- 제목과 본문 방향이 일치하는지
- 게시 가치가 있는지

### 2) 템플릿과 가이드의 구조 동기화

실제 생성물만 바꾸면 다음 자동 생성 때 다시 구조가 흔들릴 수 있기 때문에, 템플릿과 가이드를 같이 수정했습니다.

즉, 규칙을 문서로만 남긴 것이 아니라 **생성 입력과 검수 기준을 동시에 맞춘 것**이 포인트였습니다.

### 3) 고지 문구 위치 재정의

공개용 고지 문구는 유지하되, 글 목록 상단 미리보기를 과하게 차지하지 않도록 위치 기준을 조정했습니다. 이 변경은 작은 문장 이동처럼 보이지만, 실제로는 글의 첫인상과 가독성에 직접 영향을 줍니다.

### 4) 기존 초안에도 동일 규칙 반영

새 템플릿만 바꾸는 데서 끝내지 않고, 이미 생성된 전날 초안에도 같은 규칙을 반영했습니다. 덕분에 산출물과 템플릿이 서로 다른 상태로 남지 않게 정리할 수 있었습니다.

## 핵심 설정 / 코드

이번 변경의 핵심은 복잡한 로직보다도, **생성 포맷을 명시적으로 고정하는 것**이었습니다.

예를 들어 템플릿은 아래처럼 한줄 요약과 고지 문구 위치를 구조적으로 강제하도록 정리했습니다.

```md
# {{title}}

#OpenClaw #가비서 #자동화

## 한줄 요약
{{one_line_summary}}

## 배경
{{background}}

## 문제
{{problem}}

## 변경 내용
- {{change_1}}
- {{change_2}}
- {{change_3}}

## 핵심 설정 / 코드
```yaml
{{code_or_config}}
```

## 결과
{{result}}

## 정리
{{wrap_up}}

> _이 글은 하루 동안 진행한 작업을 AI로 정리한 초안을 바탕으로, 사람이 검수·수정해 게시하는 기록입니다._
```

가이드 문서에서도 같은 방향으로 검수 기준을 보강했습니다.

```md
- `## 한줄 요약` 섹션 포함 여부 확인
- 고지 문구가 글 최하단에 들어갔는지 확인
- 코드/설정 예시가 공개 가능한 수준인지 확인
```

이런 식의 변경은 프롬프트를 더 길게 쓰는 것보다 유지보수성이 높습니다. 생성 규칙을 본문 지시가 아니라 **템플릿과 가이드 파일**에 넣어두면, 이후 수정 범위가 명확해지기 때문입니다.

## 결과

작업 이후 얻은 효과는 비교적 분명했습니다.

- 초안마다 정보 배치가 덜 흔들리게 됐다.
- 사람이 검수할 때 핵심을 먼저 파악할 수 있게 됐다.
- 공개용 고지 문구의 역할은 유지하면서, 본문 가독성 문제를 줄였다.
- 템플릿, 가이드, 실제 생성물이 같은 규칙을 따르도록 맞출 수 있었다.

특히 의미 있었던 지점은, AI 글쓰기 자동화에서 품질 문제를 모델 출력 탓으로만 보지 않고 **출력 형식과 운영 규칙 문제로 분해해 해결했다**는 점이었습니다.

## 정리

AI로 초안을 만드는 자동화는 생각보다 빨리 만들 수 있습니다. 하지만 실제 게시 품질은 모델 성능보다도 템플릿, 검수 기준, 문서 구조 같은 주변 설계에서 더 많이 결정됩니다.

이번 작업은 거창한 기능 추가는 아니었지만, 초안을 "생성되는 문서"에서 "검수 가능한 게시 후보"로 바꾸는 데 필요한 기준을 세운 작업이었습니다.

비슷한 자동화를 운영한다면, 프롬프트 문장 몇 줄을 계속 손보는 것보다 아래 세 가지를 먼저 고정하는 편이 효율적입니다.

- 템플릿 구조
- 검수 체크리스트
- 기존 생성물과의 동기화 규칙
